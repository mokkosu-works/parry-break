# 試作動画の音源の再確認 (2026-11-17)

本人が「実機で聞くBGMと違う」と指摘したため、録画とゲームの音源を確認した。最初の「ゲーム内のBGMだけ」との説明は、録音経路だけを根拠に断定しており不十分だった。

## 分かったこと

- `scrcpy --audio-source=playback` は、ゲームだけに限定した録音ではない。別アプリの音声が混ざり得る。
- 端末の音声ログには、最初の撮影中に別の音楽アプリも録音先へ接続された記録があった。本人から「音楽アプリが勝手に起動していた気がする。こちらでは操作していない」と申告があった。起動・再開の原因はまだ特定していない。
- ゲームだけが再生中であることをUIDで確認し、撮影用アプリのタイトル画面の音を短く録った。これと、ゲームのコードから生成したタイトルBGMの低域の波形は、相関約0.967でよく一致した。
- 同じ手順で最初の録画の冒頭を調べると、相関は約0.286だった。短い区間の波形比較なので曲やアプリを同定するものではないが、端末ログと本人の申告も合わせ、最初の録画には別アプリの音が混ざった可能性が高いと判断した。
- ゲーム内のBGM自体はある。ゲームだけのタイトル録音は全体の平均が約−50dB、生成したタイトルBGMは約−45dBで、かなり小さい。ゲーム音を比較せず、大きく聞こえる録画の音をそのままBGMだと扱わない。
- 撮影用1.5.1と、リモートdevの最新版1.6.0 (`b08a840`) の `sound_bank.dart`・`synth.dart` はそれぞれハッシュが同じだった。
- 最新のFlutter版を一時フォルダでWeb向けにビルドしてFirefoxで画面を開いた。Webでは `createAudioService() => kIsWeb ? SilentAudio() : SoLoudAudio()` となっているので無音。本人も「音出ないね」と確認した。旧JavaScript版を一度開いてしまったが、比較対象としては使わない。

## 扱い

- `capture/raw/long-endless-akane-pilot01/` は不採用。`capture.json` を `rejected_audio_contamination`、`events.json` を `rejected: true` とし、`DO-NOT-USE.txt` を置いた。
- `build/out/akane-endless-pilot-e001/preview.mp4` も不採用。旧版は消さず、同じ出力先に `DO-NOT-USE.txt` を置いた。
- 台本作り・書き出しでは、不採用のテイクを使おうとすると止まる。
- `capture_long.py` に、撮影前と録画中の音声UIDの確認を追加。ゲーム以外の再生を検知したら、失敗として録画を止める。端末の使用中のユーザーを指定してUIDを調べる。1秒間隔での確認なので、短い音を完全に除外する保証ではない。
- 画面が消えている場合も止める。`--stay-awake` は `--no-control` と併用できず起動に失敗したため使わない。
- 録り直しの `akane-pilot02-clean` は複数ユーザーのUID表記への対応前で失敗、`akane-pilot02-clean-b` は端末の消灯により映像と出来事が取れず失敗。どちらも採用しない。本人に画面の点灯とロック解除を依頼中。
